# Optional research

Research is optional. After exploration, recommend a scoped investigation only when a named open question would benefit from external evidence. There is no fixed questionnaire, no mandatory rounds, and no completion ceremony.

- **Ownership.** The orchestrator owns product discovery: one focused question at a time, then wait. Never choose for the user or repeat settled decisions. A delegated researcher returns decision gaps instead of interviewing the user.
- **Tools.** Use documentation or web tools only when they are actually available and authorized. Prefer primary sources. Never infer access from a tool name, and never bypass permissions.
- **Delegation.** When delegating research, give `construct:general` the objective, the relevant context, the actual tool limits, and these evidence rules.
- **Evidence.** Attribute material claims to URLs or `path:line`. Separate verified facts from assumptions, contradictions, freshness limits, and gaps. Disclose unavailable tools; never present them as completed research.
- **Version-specific uncertainty.** For a named framework or library API question, load `construct:sources`: exact versions, one official page, cited URL, unverified points flagged.
- **Output.** Return concise findings, a recommendation, tradeoffs, open questions, and implementation implications. Research does not authorize implementation.
- **If declined or incomplete.** Continue authorized work where it is safe without the missing evidence. Pause only decisions that depend on it, and keep the uncertainty visible.
- **Persistence.** Keep research in the conversation unless the user asks to persist it. A transport failure is not a finding.
