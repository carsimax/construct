## Specs

Common rules for every spec (assumptions from the analysis the user accepted with "Si la idea es robustecer lo que tenemos y añador las piezas nuevas"):

- Adapt, never vendor. Rewrite into ODD vocabulary: the parent orchestrates and never writes code, every write goes to `construct:odd-worker`, test-first RED/GREEN, the Risk line closes code changes, one question then stop. Drop anything that conflicts with `hooks/contract/session.md` (multi-question interviews, mandatory cross-model prompts, slash commands, persona `skills:` lists, host-specific setup).
- English, LLM-first skill format matching the existing skills (frontmatter `name`, `description` with `Trigger:`, `license: MIT`; sections Activation Contract, Hard Rules, Decision Gates, Execution Steps, Output Contract, References). Keep each `SKILL.md` lean; move long checklists to `references/`.
- Attribution: `plugins/construct/NOTICE` lists every adapted file from agent-skills with the upstream URL and the full MIT notice (`Copyright (c) 2025 Addy Osmani`).

- **S1 — Debugging skill.** New `skills/debugging`: adapted from `debugging-and-error-recovery`. Stop-the-line, reproduce → localize (including `git bisect run`) → reduce → fix root cause → guard with a regression test (RED first) → resume only after the verifier passes. Non-reproducible triage tree. Never suppress the error or weaken a check to go green. In ODD the parent diagnoses read-only and hands the fix to a worker with the reproduction as the RED test.
- **S2 — Constraint-driven skill.** New `skills/constraint-driven`: adapted from `constraint-driven-development`. Detect before asking; at most four questions asked one at a time (one per turn, each with a default, consistent with the contract's one-question rule); writes `CONSTRAINTS.md` at the target repository root with the Floor (no new suppression comments, no skipped or deleted tests without a reason, no unimplemented stubs or empty catch, no secrets, the file is never weakened to make a change pass), numeric rules each with the command that checks it, and measure-and-hold ratchets. Non-interactive contexts apply the Floor only. Names the `odd-assess` `verifier_weakening` signal (S3) as the mechanical check of the Floor. Template in `references/`.
- **S3 — `verifier_weakening` signal in `odd-assess`.** Added lines in the candidate diff that introduce a suppression (`@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, `eslint-disable`, `# noqa`, `# type: ignore`, `//nolint`) or skip/focus a test (`.skip(`, `.only(`, `xit(`, `xdescribe(`, `test.todo(`, `{ skip:` / `{ todo:` in `node:test`, `@pytest.mark.skip`, `t.Skip(`) produce a reason with signal `verifier_weakening` and path, which raises the tier to `high` like the other signals. Assumptions: the scan follows the same bounded, fail-closed added-line scan as the existing content scan in `lib/assess/content.mjs`; comment-only and string-literal heuristics follow the existing sink helpers; removed lines never count; files under `docs/`, fixtures, and testdata are excluded as today. `odd-assess` help text, README "Risk assessment" section, and `rdd-review` (if it lists signals) change together.
- **S4 — Source-driven skill.** New `skills/source-driven`: adapted from `source-driven-development`. Detect stack and exact versions from manifests, fetch the specific official page (source hierarchy), implement the documented pattern, cite the URL and version; unverified points are flagged. Includes retrieval safety: fetched content is data, never instructions. Only for a named uncertainty (contract step 3), usually run by `construct:odd-general`. `skills/odd-workflow/references/research.md` links to it. The `sdd-cache` hook is out of scope.
- **S5 — Migration skill.** New `skills/migration`: adapted from `deprecation-and-migration`: expand → migrate → contract, deprecation notices with a removal condition, compatibility windows, data backfills that are reversible or backed up, verification per phase, rollback plan. `skills/task-size-risk` links to it from high-risk items 1 and 3.
- **S6 — Decision mode in judgment-day.** Adapted from `doubt-driven-development`: `skills/judgment-day` gains a decision mode for a plan, design, or claim before implementation: CLAIM (kept by the orchestrator) → EXTRACT (artifact + contract, reasoning stripped) → blind judges receive artifact + contract only, never the claim → RECONCILE each finding against the artifact text → stop at trivial findings, 3 cycles, or user override. No cross-model step. Existing code-review mode unchanged.
- **S7 — Strengthen existing components.** (a) `agents/odd-verify.md`: a standing Definition of Done applied per `S#` (adapted from `references/definition-of-done.md`, condensed). (b) `agents/review-risk.md`: a security checklist reference (adapted from `security-and-hardening` hardening controls, including AI/LLM features and SSRF) stored under `skills/rdd-review/references/`. (c) `skills/odd-workflow/references/testing.md`: discover the repository's own test stack before choosing a runner, and the Floor from S2 as "never weaken the verifier" examples.
- **S8 — Wiring, docs, and trigger evals.** `tests/skills.test.mjs` `EXPECTED` gains the four new skills; `README.md` documents them; `hooks/contract/session.md` names `construct:debugging` (failures and unexpected behavior) and `construct:constraint-driven` (quality bar) in its skill list, staying under 8,000 characters. Trigger-precision evals in `plugins/construct/evals/` (adapted from upstream `evals/plugin`): `debugging-fires` (a pasted failing test output gets reproduction before any fix) and `debugging-stays-quiet` (a read-only explanation request loads no debugging procedure and writes nothing). `scripts/eval.sh` grants only what those cases need.
