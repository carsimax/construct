Objective: finish porting gentle-ai to Construct after the v4.2.0 gap map. Keep Construct's receipts and denying publication gate (a deliberate hardening; upstream's live compact v2 flow publishes no receipts and its `validate` never denies), and port the live v2 review behavior, the path-identity fix, and the prompt rules Construct lost. ## Specs

- **S1 — Path identity in write-scope.** Source: gap map item 1, reproduced: on a case-insensitive volume a differently-cased `file_path` or `cwd` bypasses S4 (main thread does not write) and S3, because `write-scope.mjs:27,50` uses `realpathSync`, which keeps the caller's case. Compare canonical on-disk paths (`realpathSync.native`) for the root, the nearest existing ancestor, and surfaces, as `U/pathidentity/identity.go:61-110` does by file identity. Unicode NFC/NFD: test on this volume; if the native path does not canonicalize it, record the limit.
- **S2 — Refuter inconclusive goes to correction.** `U/reviewtransaction/compact.go:1335`: a severe finding the refuter answers `inconclusive` joins the fix set, as `corroborated` does. Today `lib/review/commands.mjs:332` moves it to advisory.
- **S3 — Causality and evidence vocabulary.** `U/reviewtransaction/transaction.go:50-66`: accept causal dispositions `behavior-activated` and `worsened` (candidate-caused, like `introduced`) and evidence class `insufficient`. Reducer as `compact.go:1290-1330, 1856-1892`: an `insufficient` or `unknown` severe finding is inconclusive, never confirmed or dropped silently. Lens prompts list the accepted values.
- **S4 — Finding admission.** `U/reviewtransaction/artifact_admission.go:505-682`: a location is `path:line` or `path:start-end` with positive, ascending lines and a canonical relative path inside the candidate's paths; duplicate finding ids are refused; a candidate-caused severe claim whose location touches no changed line is downgraded to `unknown`. Refusals keep the existing `invalid_result` code with a message naming the rule.
- **S5 — Validator inconclusive retries.** `U/reviewtransaction/compact.go:290`: a validator `inconclusive` is a non-verdict that may be re-captured, up to 3 attempts per lineage; `unresolved`, or a 3rd `inconclusive`, escalates as today.
- **S6 — RDD switch freezes mutations.** Upstream refuses authority mutations with `rdd_disabled` when RDD is off, reads stay available. `odd-review` verbs that change a lineage (`start`, `capture*`, `correct`, `acknowledge`, `abandon`, `invalidate`) refuse with `rdd_disabled` when `mode` is off; `status`, `context`, `validate`, `mode`, and reads still work. The review hooks already stay silent when off.
- **S7 — Request context for lenses.** `U/cli/review_facade.go:2202`: `odd-review start --request-context <file>` freezes the request or spec text (byte-capped like other context) into the lineage, and `odd-review context` shows it to every lens. `rdd-review` tells the orchestrator to pass the feature document's specs.
- **S8 — Verifier, worker, and lens rules.** Port behavior-changing rules: `odd-verify.md` from `U/assets/opencode/agents/gentle-ai-verify.md:11-20` (a verdict per spec, unverifiable counts as unmet, the writer's tests are never evidence, typecheck/build and out-of-scope change check, scratch copy without `.git`/worktree/stash with `HOME` and `TMPDIR` inside it, unexpected mutation is a blocker, recheck limited to reported blockers plus direct regressions); `odd-worker.md` from `gentle-ai-worker.md:59` (one correction per failing check, a second only after a real fix, then `partial`; `git status --short` before returning); `review-readability`, `review-reliability`, `review-resilience` get upstream's concrete `Review rules` lists from `U/assets/claude/agents/review-*.md`.
- **S9 — Orchestration rules.** In `odd-delegation` (not the session contract, which is near its budget): one verifier at a feature's end, per unit only when the unit's Risk line names an item (`U/assets/skills/_shared/odd-orchestrator-sections.md:19`); sub-agent launch deduplication; the native checking contract (normalize before verification, unavailable proof is never a pass, docs-only gets a readback, not a verifier); sub-agent memory protocol (the parent passes engram context; subagents save validated facts with `mem_save` and do not search engram, except `odd-explorer`).
- **S10 — odd-assess exit code.** Without `--json`, an `unassessable` result exits non-zero (upstream returns an error); with `--json` the output is unchanged. Help text and README together.
- **S11 — Explicit model wins.** Source: this session, explorers launched with `model: "opus"` ran on haiku because `hooks/register.js:314` applies `model_<role>` over the call's `model`. An explicit `model` on the Agent call wins; `model_<role>` is the default when the call names none.

Out of scope (decided in this gap map): native `permissions.deny` seeding (secret-guard is a superset), installer uninstall and backup retention, `issue-creation`, model presets, telemetry, v2 receipt burning and the non-denying gate, rename-aware `changed_lines`, upstream's refusal (not escalation) of a second correction, raising the 400 KiB context default (4 MiB cannot fit a lens prompt; documented as deliberate).
