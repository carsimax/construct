# Mandatory RDD

Objective: make review a mandatory ODD phase for high-risk work, enforced by small hooks, and delete the deterministic RDD machinery (`lib/review`, `lib/assess`, their CLIs). Baseline `d09ceba` (main, 2.1.0). Branch: `feat/mandatory-rdd`. Delivery strategy: single-pr (whole-file deletions dominate, as in `15826e4`). Test runner: `node --test tests/`; `claude plugin test plugins/construct`; `claude plugin validate --strict .` and `--strict ./plugins/construct`.

## Specs

Source: L1-L4. Design accepted in L3 ("ok me parece excelente asi"), docs research in L5.

- **S1 — Shared git helpers survive.** `risk-line.mjs` and `mirror-drift.mjs` keep their behavior without `lib/`. The helpers they use (`git`, `repositoryRoot`, `freezeWorkingTree`, `headCommit`, `atomicWrite`, and what those need; about 85 lines, L6) move into one module under `hooks/scripts/`. Test helpers in `tests/review/helpers.mjs` that `tests/risk-line` and `tests/mirror-drift` import move with them, out of `tests/review/`. Existing risk-line and mirror-drift tests pass unchanged in substance.
- **S2 — Review is mandatory for high-risk work.** "podemos hacer que rdd sea obligado, es decir una fase obligada del odd?" (L2). The protocol becomes Implement → Review → Close: a work unit whose Risk line names an item gets reviewed before publication. Scope: only high-risk work (Risk names an item), per the recommendation accepted in L3. There is no on/off switch: `odd-review mode` and its global/clone mode files stop being read.
- **S3 — Lenses follow the risk items.** Assumption (from the design in L3, not the user's words): the required lenses come from the Risk column numbers of the feature document's tasks: 1 → `review-risk`, `review-resilience`; 2 → `review-risk`; 3 → `review-reliability`; 4 → `review-reliability`, `review-resilience`; 5 → `review-risk`, `review-resilience`; 6 → `review-reliability`. `review-readability` is optional. The mapping lives in one place in code and is quoted by the `rdd-review` skill.
- **S4 — Lens context from a hook.** The lenses keep `tools: []`. A PreToolUse hook on `Agent` for `construct:review-*` reads the review subject from the prompt (`Review subject: <base>` or `<base>..<head>`; head defaults to `HEAD`, L15), builds the context itself (binding, name-status, the diff with deleted paths listed but their removed content omitted, and the `review-risk` security checklist), computes `subject_hash` from the base and head trees, and records the pending lens. A review agent whose prompt names no readable subject is denied with the expected form. The orchestrator never pastes evidence.
- **S5 — The verdict is recorded by a hook, never by the orchestrator.** A SubagentStop hook on `^construct:review-` takes the lens report from `last_assistant_message` (transcript fallback for background agents, as today), validates it against the lens result shape the agents already return (`subject_hash`, `inspection`, `findings`, `evidence`), requires its `subject_hash` to match the pending record, and writes one record per lens to a store under the git common dir. A malformed result blocks the subagent with the reason, at most twice. Approved means no BLOCKER or CRITICAL finding. The refuter and validator steps are dropped (assumption: the mandatory phase is one round; a rejected review is fixed and re-run).
- **S6 — Publication gate.** Before `git push`, `gh pr create`, or `gh release create` (existing parsing in `publication-gate.mjs` and `shell-words.mjs`), the gate judges every ref being published (push sources, `gh pr create --head`, `gh release create --target`; `HEAD` when none is named, L15): it finds the feature documents changed from the merge-base with the default branch to that ref, collects every Risk number 1-6 of their tasks (a cell that is neither `none` nor readable denies), and denies while any required lens of S3 lacks approval from the merge-base tree to the ref tree, either one approved subject or a chain of approved subjects. A rejection of a subject stands; only a new subject can be approved. A thrown error denies. The denial names the missing lenses and the `construct:rdd-review` skill. New commits change the subject, so the review must re-run. Its hook entry sets `onFailure: "block"` (Claude Code 2.1.295+, L5); the minimum Claude version is already 2.1.304 (`hooks/status/doctor.js:6`, `install.sh:12`, L11), so it does not change. Writes to the review store through Write, Edit, or a Bash command naming its path are denied (heuristic guard, L5).
- **S7 — Deterministic machinery deleted.** "no se que tanto podemos quitar el codigo determinista y dejar el trabajo a skills,hooks,agentes para que se haga un trabajo similar" (L1). Delete `lib/review/`, `lib/assess/`, `bin/odd-review`, `bin/odd-assess`, `hooks/scripts/review-gate.mjs`, the `review-refuter` and `review-validator` agents and their `userConfig` pairs, their `hooks.json` entries, their tests, and the panel REVIEW card and doctor rows that read the CLIs. Nothing left in the plugin invokes `odd-review` or `odd-assess`. `delivery-signals.mjs` stays (L8): its one `lib/` import, `isGeneratedGoldenPath` (`lib/assess/stats.mjs:16-19`), moves into `hooks/scripts/`, and its tests in `tests/signals/` stay, repointed off `tests/review/helpers.mjs`.
- **S8 — Text follows the code.** The session contract states the mandatory phase in place of the RDD switch section and stays within the contract test budget (about 7,410 characters today, L6). The `rdd-review` skill and its references describe the new flow; `task-size-risk`, `constraint-driven`, `judgment-day`, README, CONTRIBUTING (consistency table, example test), and CLAUDE.md drop the CLIs and the switch.
- **S9 — Release 3.0.0.** Major: CLIs, the mode switch, and two agents' config keys are removed. Follow CONTRIBUTING "Releases" and the 2.0.0 precedent (`4320200`). Tag only after the user merges.
- **S10 — Delegation forms are documented where the model reads them.** "metelo como tarea" (L14), for the proposal in L13. Every requirement `delegation-admission.mjs` enforces on a launch appears in the matching handoff template: `Risk: item N (reason)` for `construct:odd-verify` in `skills/odd-delegation/references/handoffs.md` and `skills/odd-delegation/SKILL.md`; the worker's `Spec:` line and `## Allowed edit surfaces` with one bare path or glob per line and notes under a later heading. The session contract's Delegation section names these forms in one line, within the contract budget. A test fails when a requirement the hook enforces is missing from its template. The hook itself is not loosened.
- **S11 — Audit fixes.** "Vamos por los 20 hallazgos" (L26): fix the twenty findings of the repository audit recorded in L25 (F1-F20), each with a test where it changes logic. F17 removes the chain of approved ranges (`<base>..<head>`, `approvedLinks`, `chainExists`, `rejectedTrees`), which supersedes the chain clauses of S4 and S6 and resolves A1 (L23): the gate accepts one approved subject from the merge-base tree to the ref tree, a branch whose context exceeds the limit is denied with a request to split the delivery, and a rejection of a subject stands.
