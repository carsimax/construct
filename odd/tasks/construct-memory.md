# Construct memory

Objective: replace the `engram@engram` dependency with a per-repository memory built into the plugin: one SQLite + FTS5 database under the git common dir, a CLI on the Bash tool's PATH, and hooks, with no MCP server and no external binary. Baseline `2b5930f` (main, 3.0.0). Branch: `feat/construct-memory`. Delivery strategy: chained PRs (L34): PR 1 `2b5930f..c478f21` (T1-T12, T17) and PR 2 from `c478f21` (T13 on), each reviewed on its own range; first single-pr (assumption, as in `odd/tasks/mandatory-rdd.md`). Test runner: `node --test tests/`; `claude plugin test plugins/construct`; `claude plugin validate --strict .` and `--strict ./plugins/construct`.

## Specs

Source: L1-L3, map in L4. Engram references are to commit `258e7a3` of github.com/Gentleman-Programming/engram (MIT); behavior is ported, code is not copied, and the name "Engram" is not used for the new parts (trademark, L4).

- **S1 — One database per repository.** "una db de SQLite + FTS5 por repo" (L1); "<git common dir>/construct-memory/" (L3). The store is `<git-common-dir>/construct-memory/memory.db`, opened with `node:sqlite` (no npm dependency), so every worktree of a clone shares it and nothing is committed. No `project` column and no `scope`: the database is the project (assumption from L4: `personal` and `global` have no home in a per-repo store). Pragmas and concurrency as engram (`internal/store/store.go:1195-1215`, `:10180-10195`): WAL, `busy_timeout` 5000, `BEGIN IMMEDIATE` for writes, up to 5 retries with 10-200 ms backoff on `SQLITE_BUSY`. Schema versioned with `PRAGMA user_version`; a newer version than the code knows is refused with a message, never rewritten. Outside a git repository the memory is off and every command and hook says so or stays silent (assumption). Node 22's `ExperimentalWarning` for `node:sqlite` never reaches stderr of a hook or the CLI.
- **S2 — Schema.** Tables `observations` (`id`, `session_id`, `type`, `title`, `content`, `topic_key`, `normalized_hash`, `revision_count`, `duplicate_count`, `last_seen_at`, `review_after`, `created_at`, `updated_at`, `deleted_at`), `observation_versions`, `sessions` (`id`, `started_at`, `ended_at`, `summary`), `user_prompts` (`id`, `session_id`, `content`, `created_at`), and the external-content FTS5 tables `observations_fts` (`title`, `content`, `type`, `topic_key`) and `prompts_fts` (`content`) with `tokenize='trigram'` and triggers that drop soft-deleted rows from the index (engram `store.go:1440-1561`, `:3150-3194`).
- **S3 — Write rules, as engram.** On save (`store.go:4246-4411`): `<private>…</private>` becomes `[REDACTED]` in title and content; content is capped at 50,000 bytes on a UTF-8 boundary with `... [truncated]`; a `topic_key` (at most 120 bytes, cut on a character boundary) upserts the newest live row with that key after saving its previous state to `observation_versions`; otherwise the same normalized hash, type, and title within 15 minutes increments `duplicate_count` instead of inserting. `review_after` from the type in months: decision 6, policy 12, preference 3, config 3, discovery 6, pattern 6, architecture 12, bugfix 12; other types none (`store.go:435-449`). `needs_review` is derived at read time. Update: by id, content or find/replace (not both), versioned first. Delete: soft by default (`deleted_at`).
- **S4 — Search and context, as engram.** Search (`store.go:5716`, `:6022-6168`): default 10, max 20 results; a query containing `/` also matches `topic_key` exactly and ranks first; any term shorter than 3 characters falls back to an escaped `LIKE` scan; otherwise each term is quoted (`"` doubled) and joined with AND (`--any` for OR); rank bm25 with weights title 5, content 1, topic_key 3, plus recency (+0.06, 30-day half-life) and stability (+0.04) boosts; previews truncated, full text through `get`. Context (`FormatContextWithOptions`, `store.go:6320`): `## Memory from Previous Sessions` with the 5 most recent sessions (summary cut at 200 characters), 10 prompts (200 characters), 20 observations as `- [type] **title**`, capped at 16,384 bytes with `[truncated]`.
- **S5 — CLI, no MCP.** "para no depender de un mcp mas" (L1). One executable in the plugin's `bin/` (on the Bash tool's PATH, as `bin/odd-review` was at `d09ceba`), name `construct-memory` (assumption): `save` (JSON on stdin: `title`, `content`, `type`, `topic_key`, `session_id`), `search <query> [--type] [--limit] [--any]`, `get <id> [--history]`, `context`, `update <id>` (JSON on stdin), `delete <id>`, `summary --session <id>` (content on stdin; stores the session summary and ends the session), `review list|done <id>`, `import <file>` (S7). Output is compact text for the model; errors exit non-zero with one line. Pin, timeline, consolidation, and conflict judging are out of scope (L4).
- **S6 — Hooks.** All exec form, fail open, silent outside a repository.
  - `SessionStart` (`startup|resume|clear`): registers the session and emits the S4 context plus one line naming the session id and the CLI.
  - `SessionStart` (`compact`): the same, plus engram's recovery instruction (`plugin/claude-code/scripts/post-compaction.sh`): save the compacted summary with `construct-memory summary --session <id>` first.
  - `UserPromptSubmit`: stores the prompt; skips empty prompts and those starting with `<task-notification>` or `<agent-message` (`internal/server/prompt_capture_decision.go:13-46`).
  - `SubagentStop`: passive capture from `last_assistant_message`: the last `##`/`###` section titled `Key Learnings`, `Learnings`, or `Aprendizajes (Clave)`; numbered items, else bullets; markdown emphasis stripped; kept when at least 20 characters and 4 words; deduplicated by normalized hash; type `passive`, title cut at 60 characters (`store.go:13766-13900`).
  - The save reminder after 15 minutes without a save (`user-prompt-submit.sh:781-801`) is kept, one line.
- **S7 — Import from engram.** One-shot `construct-memory import <file>` reads the JSON written by `engram export` (versions `0.1.0` and `0.2.0`, `store.go:716-717`, `:759`), takes the observations, sessions, and prompts of one project (`--project <name>`; required when the file holds several), skips deleted rows, keeps original timestamps, and is idempotent (re-running inserts nothing new). It never opens `~/.engram`. It reports counts.
- **S8 — No engram dependency.** Remove `engram@engram` from `plugin.json`, the cross-marketplace allowance from `marketplace.json`, engram's steps and permission rules from `install.sh` (the installer never uninstalls engram; it prints one line saying it is no longer needed), `checkEngram` from the doctor (replaced by a `node:sqlite` check), the `mcp__engram__*` tools from agent frontmatter, and the eval workaround that drops the dependency (CONTRIBUTING "evals"). `MIN_NODE` rises from 20 to 22.16, the first release where `node:sqlite` loads without a flag and has FTS5 trigram (L7), in `hooks/status/doctor.js`, `install.sh`, and the docs; the docs say Node 23 is unsupported (no `fts5` module in 23.11, L7).
- **S9 — The feature-document mirror goes.** From the analysis accepted in L1-L3: `odd/tasks/*.md` are versioned by git, and nothing reads the engram copy (`feature-state.mjs` reads the local files). Delete `mirror-drift.mjs`, its hook entry and tests, and every "engram mirror" rule (contract, `odd-workflow`, `persistence.md`, `task-size-risk`, `odd-delegation`, `feature-state.mjs` footer). The feature documents stay in `odd/tasks/` (L5, L6).
- **S10 — Text follows the code.** The session contract names the new memory in place of engram and stays under the 8,000-character budget. A `memory` skill replaces engram's protocol: when to save (decision, bug fix with root cause, discovery, convention, preference), format (What / Why / Where / Learned), `topic_key` for evolving topics, search order (context, search, get), session summary sections (Goal, Instructions, Discoveries, Accomplished, Next Steps, Relevant Files), and `## Key Learnings:` for passive capture. `odd-delegation` (parent searches memory and passes it; subagents with Bash may search), the output style's language rule, README, CONTRIBUTING, CLAUDE.md, and `NOTICE` (engram attribution, MIT).
- **S11 — Release 4.0.0.** Major: the engram dependency, its MCP tools in agents, and Node 20 support are removed. Follow CONTRIBUTING "Releases"; release notes say how to import (S7) and that `engram@engram` can be uninstalled. Tag only after the user merges.

- **S12 — Stored prompts can be deleted.** "Si vamos con tus recomendaciones" (L16), accepting L14 W2: `construct-memory prompts [--limit N]` lists recent stored prompts with their id, date, and a preview; `construct-memory prompts delete <id>` removes one for good (row and FTS index), as engram's hard prompt delete. A deleted prompt that came from an import is never re-imported (a tombstone of its import key; assumption, as engram's `prompt_tombstones`). The `memory` skill and README name both commands.

- **S13 — Stored observations can be erased.** "Tu sigue proponiendo y metiendo las recomendaciones" (L21), accepting L20 W4: `construct-memory delete <id> --hard` removes the observation row, its `observation_versions`, and its FTS entry for good; plain `delete <id>` stays a soft delete (S3). A hard-deleted observation that came from an import is never re-imported (a tombstone of its import key, as S12 does for prompts). The `memory` skill says to use `--hard` for anything sensitive, and README names it.

- **S14 — Export for backup and moving between machines.** Parent recommendation under L21, from the parity question in L22: the database lives in the git common dir, so a fresh clone or another machine starts empty and engram's sync is out of scope (L3). `construct-memory export [file]` writes live observations, sessions, and prompts as JSON in the shape `import` reads (version `0.2.0`, one project named after the repository directory), to stdout or the file; `import` of that file into another clone restores them, and re-importing changes nothing. Soft- and hard-deleted rows are not exported. README and the `memory` skill name it.

- **S15 — Topic keys, timeline, pins, stats.** "podemos portear suggest_topic_key, timeline, pin, unpin, stats, doctor, judge, judge_many, compare, consolidate?" (L24). `construct-memory suggest-topic-key` (JSON on stdin: `type`, `title`, `content`; prints a key, no write; engram `SuggestTopicKey`), `timeline <id> [--before N] [--after N]` (same-session neighbours by id, default 5 and 5; engram `Timeline`, `store.go:5606`), `pin <id>` / `unpin <id>` (a `pinned` column; pinned observations get their own context section, at most 20, and the +0.10 search boost of S4; engram `store.go:4469-4504`, `:6022-6070`), `stats` (counts of live, soft-deleted, needing review, pinned observations, sessions, prompts, database size), and `prompts --search <query>` over `prompts_fts` (engram `SearchPrompts`, `store.go:5046`; parent recommendation under L21, L25).
- **S16 — Doctor.** (L24) `construct-memory doctor [--json]`: schema version, `PRAGMA integrity_check`, the FTS5 `integrity-check` of both indexes, orphaned versions, WAL mode, the `db_id`, and whether the file is writable; one line per check, `ok` or the problem with a hint, non-zero exit when one fails. Read-only (no repair).
- **S17 — Relations and judging.** (L24) A `memory_relations` table (source, target, relation, status `pending`/`judged`, reason, evidence, confidence, timestamps; engram `relations.go:52`, `:376`, `:626`, `:788`). After `save`, up to 3 candidates (FTS OR over the saved title, live rows, excluding pairs already judged) are recorded as pending and printed under the save line with their judgment ids. `judge <judgment-id> <relation> [--reason] [--evidence] [--confidence]`, `judge-many` (JSON array on stdin, 1-32 items), and `compare <id-a> <id-b> <relation> --confidence <0..1> [--reasoning]` record verdicts; relations are `related`, `compatible`, `scoped`, `conflicts_with`, `supersedes`, `not_conflict`; confidence in [0,1]. `search` and `get` mark `conflicts_with` and `supersedes` relations. Judging is never mandatory: the `memory` skill says to judge a candidate only when it really conflicts or supersedes and to ask the user when confidence is below 0.7 or the relation is `supersedes`/`conflicts_with` on a decision or architecture memory (assumption: the parent's recommendation under L21, to avoid engram's one-call-per-candidate cost noted in L4).
- **S18 — Consolidate.** (L24) `consolidate <id> <id>... --title T` (content on stdin) prints a preview and a fingerprint without writing; `--confirm <fingerprint>` creates the merged observation, soft-deletes the sources, and records `supersedes` relations from the new one to each source, in one transaction; a changed source (fingerprint mismatch) is refused (engram `consolidate.go:122`, `internal/mcp/consolidate.go:22`).

- **S19 — Memory has a role across the harness.** "Al final asegura que todo el harnees realmente ocupe nuestra memoria y le de una razon de ser" (L30). Each touchpoint names when memory is read and what is written, so memory is part of the ODD loop rather than an optional tool:
  - Session contract (within its 8,000-character budget): Explore starts with `construct-memory search` on the feature or area; Close saves the decisions, root causes, and conventions learned, and large work stores the session summary.
  - Subagent contract: every subagent that receives it ends its report with `## Key Learnings:` (numbered, standalone facts), so passive capture does not depend on each handoff; JSON-only reviewers stay excluded.
  - `odd-workflow` (explore, close, resume) and `references/persistence.md` (resume reads the injected context and searches the feature name); `odd-delegation` handoff template carries a `Memory:` section with the hits the parent passes.
  - `debugging`: search the symptom or error before reproducing; save the root cause as `bugfix` after the fix. `rdd-review`: a rejected finding's root cause and fix are saved as `bugfix`; a deferred advisory as a `decision`. `constraint-driven`: quality-bar decisions saved under `topic_key` `quality/<rule>`. `migration`: the chosen plan under `migration/<name>`.
  - Agents: `odd-explorer` searches memory before mapping; `odd-worker`, `odd-general`, and `odd-verify` end with `## Key Learnings:`.
  - `/construct doctor` runs the memory doctor (S16) in a git repository and shows its result lines.
  - An eval case (`memory-recall`) whose fixture seeds a decision through the CLI; graders check that the agent searched memory and honored the decision.
  - A repository test pins the touchpoints (contract and skills name `construct-memory` where listed above) so they cannot vanish silently.

- **S20 — Memory card in the panel.** "Me gustaria tambien en el panel que tenemos agregar una card que ayude a estaer al tanto de la meoria" (L31). A `MEMORY` card in the status panel (`hooks/panel/layout.js`, beside the ODD and GATE cards) fed by the mod's `collect` on session start and turn complete, from `construct-memory stats --json` (new flag; the CLI stays thin): status `<N> memories`; a row with `<n> to review` (amber when above 0), `<n> pinned`, `<n> pending` relations; a row with `last save <age>` and `+<n> this session` (observations saved in the current session). When memory is off (outside git, or `node:sqlite` unusable) the card shows one dim line saying why; when the database is empty, `no memories yet`. It fails like every other panel source: a gap leaves the card out, never breaks the event.

- **S21 — Review advisories on PR 1 (L40).** Parent recommendations under L21: (a) an unclosed `<private>` redacts to the end of the text, on every write path; (b) erasing is real: the database runs with `PRAGMA secure_delete = ON`, and `delete --hard` and `prompts delete` also merge the FTS index (`'optimize'`) and checkpoint the WAL (`wal_checkpoint(TRUNCATE)`), so erased text is not left in free pages, index segments, or the WAL; (c) memory failures are visible: when the store cannot open (newer schema, unwritable, no fts5), the SessionStart hook injects one line `Memory: unavailable (<reason>); run construct-memory doctor` instead of nothing, and the MEMORY card shows the reason instead of disappearing; (d) the installer pre-approves only the non-destructive commands (`search`, `get`, `context`, `timeline`, `stats`, `doctor`, `suggest-topic-key`, `save`, `update`, `summary`, `review list`, `prompts` listing and `--search`, `pin`, `unpin`, `judge`, `judge-many`, `compare`, `help`), so `delete`, `prompts delete`, `consolidate`, `import`, `export`, and `review done` keep asking; README says so.
