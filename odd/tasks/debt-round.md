A boolean plugin option `command_guard_asks` (default `false`). With `false`, command-guard emits no `ask` decision: commands it would ask about (recursive force `rm`, `git push --force` without a lease, `git reset --hard`, `git clean -f`, `git checkout .`, `git restore` at a root, `find -delete`, `find -exec rm -rf`, `xargs rm -rf`) pass without a prompt. With `true`, the asks are as today. Denies (verifier bypasses: `--no-verify`, `--no-gpg-sign`, hooks-path config) are unaffected by the option. When a command matches both a deny and an ask, it is still denied. publication-gate and review-store-guard are unchanged. Docs: README options table and the command-guard description, session contract or skills wherever they say command-guard "asks". Behavior change for every user (Risk 2, 3): noted in the PR and the next release notes.
