# Memory MCP server

Objective: Claude reaches construct-memory through native, typed MCP tools named like engram's, with the CLI kept as the fallback and as the single implementation. Branch: feat/memory-mcp. Baseline: a4e7cb6. Delivery strategy: single-pr. Test runner: `node --test tests/`.

## Specs

- **S1 — The plugin ships one MCP server, its own.** "F4. Interfaz nativa (MCP) ... Un servidor MCP stdio dentro del plugin, sin dependencias y sobre el mismo `memory-store.mjs`." `plugins/construct/.mcp.json` declares exactly one server, `memory`: `command: "node"`, `args: ["${CLAUDE_PLUGIN_ROOT}/hooks/scripts/memory-mcp.mjs"]`. The script imports only `node:` modules and plugin files. The earlier test "the plugin ships no MCP servers" (it came from removing third-party codegraph, decision #8: no third-party dependencies) becomes "the only MCP server is the plugin's own memory server".
- **S2 — Protocol.** MCP over stdio: newline-delimited JSON-RPC 2.0 on stdin/stdout, nothing on stderr in normal operation. `initialize` answers `{ protocolVersion: <the client's requested version, else "2025-06-18">, capabilities: { tools: {} }, serverInfo: { name: "construct-memory", version: <plugin.json version> } }`; `ping` answers `{}`; `tools/list` lists the S3 tools with `name`, `description`, and an `inputSchema` (JSON Schema object, `required`, `additionalProperties: false`); `tools/call` runs one tool. Messages without an `id` (notifications) get no answer. An unknown method with an id answers error -32601; an unknown tool or arguments that fail the schema answer error -32602 with a message naming the problem; a line that is not JSON answers error -32700 with `id: null`. The server exits when stdin closes.
- **S3 — Tools, engram names, CLI semantics.** "Expondría `mem_save`, `mem_search`, `mem_context`, `mem_get_observation`, `mem_session_summary`, `mem_judge`, `mem_timeline` y `mem_update` con esquemas tipados." Plus `mem_suggest_topic_key` and `mem_relations_pending`. Each call runs `bin/construct-memory` once with an argument array (no shell; options before a `--` that precedes free-text positionals), JSON or text on stdin where the CLI reads it, a 10-second timeout. Mapping: `mem_save {title, content, type?, topic_key?, session_id?}` → `save` (stdin JSON); `mem_search {query, type?, limit?, any?}` → `search`; `mem_context {}` → `context`; `mem_get_observation {id, history?}` → `get`; `mem_update {id, title?, content?, type?, topic_key?}` → `update <id>` (stdin JSON without id); `mem_timeline {id, before?, after?}` → `timeline`; `mem_session_summary {session_id, content}` → `summary --session` (content on stdin); `mem_judge {judgment_id, relation, reason?, evidence?, confidence?}` → `judge`; `mem_suggest_topic_key {type?, title?, content?}` → `suggest-topic-key`; `mem_relations_pending {limit?}` → `relations pending`. Result: `{ content: [{ type: "text", text: <CLI stdout> }] }`; a CLI exit other than 0 gives `isError: true` with the stderr line as text; a timeout gives `isError: true` and `construct-memory timed out`. The CLI runs in `CLAUDE_PROJECT_DIR` when set, else the server's cwd.
- **S4 — No destructive tool.** "El CLI se queda como fallback." `delete`, `prompts delete`, `consolidate`, `import`, `export`, and `review done` have no tool; they stay CLI-only and keep asking.
- **S5 — Permissions and docs.** "es superficie nueva consumida y toca el entorno del plugin (Risk items 3 y 5)". `install.sh` pre-approves each S3 tool by exact name (`mcp__plugin_construct_memory__<tool>`). The SessionStart Memory line names the tools; README (MCP servers and Memory sections), CLAUDE.md, and the memory skill describe the server and that `construct:explorer` (fixed tool list) and the CLI fallback keep working.
- **S6 — Live check.** A `claude -p` session with the plugin loaded lists and calls `mcp__plugin_construct_memory__mem_context` against a scratch repository and gets that repository's context.
- **S7 — Release 8.5.0 and PR.** "DAle al pr". Bump as in 8.4.0, push the branch, open the PR.
