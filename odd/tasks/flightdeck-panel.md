Objective: make the docked Construct panel look and work like claude-flightdeck, reusing its MIT drawing code with attribution, adapted to the ODD cycle. Branch: `feat/flightdeck-panel`, baseline `4c5d3d7` (main). Delivery strategy: ask-on-risk. Test runner: `claude plugin test plugins/construct` (mod), `node --test tests/` (repository), `claude plugin validate --strict ./plugins/construct`.

Relevant files: `hooks/register.tsx` (cards at `:606-955`, header `:1104-1121`), `hooks/core.ts` (`gauge` `:251-254`, `bucketOf` `:302-303`, bucket totals `:331-349`, `lanes` `:452-463`), `hooks/rail.tsx`, `hooks/elapsed.tsx`. ## Specs

- **S1 — No band, open by default, one layout.** "necesito que este siempre en el modo mini y que pod defecto este vible, lo comento para que todo este adeucado a eso, cada elemento que muestro debe ocupar una fila para aprovecharlo al maximo y la banda inferior desaparece completamente". The `AbovePrompt` band is gone, `panel_open_on_start` defaults to `true`, and the panel has one single-column layout at any width. Assumption: flightdeck's two-column split at 110+ columns is not adopted, because the user asked for one layout.
- **S2 — Flightdeck look.** "Lo quiero exactamente como https://github.com/scasella/claude-flightdeck pero con las adecuaciones adicionales del ciclo de odd". As in its docked pane: a centered header (`CONSTRUCT · <MODEL> <IDLE|BUSY> · ODD <task>`) with a `■` color legend (main, agents, gate, odd, review); `round` bordered cards with the bold title on the left and the status on the right; the animated rail with dots between cards; `▮▯` effort meter, `▰▱` gauges; theme colors only. The pane asks for flightdeck's `columns: 66` (assumption: replaces the earlier 56 request; still a request, not a guarantee, as the user was told).
- **S3 — Main card.** As flightdeck's main card: `<Model> · main`, idle or busy, effort meter, permission mode, request count, ctx gauge with tokens used/limit, session cost, 5h and 7d mini gauges. Assumption: shown whether or not the user has a `statusLine` (flightdeck does). Assumption: dir, git and output style are not shown, because flightdeck does not show them.
- **S4 — ODD card (replaces flightdeck's ARCHITECT card).** Assumption, from the accepted proposal: `ODD · <feature>` title, the current task id and title, a progress line with one checkpoint per task (done filled, current highlighted), and the open count. Hidden when no feature is active.
- **S5 — REVIEW card.** Assumption, from the accepted proposal: RDD mode (on/off) and its state (clear, due, ...) from the data already gathered. Hidden when RDD has nothing to show.
- **S6 — GATE card.** As flightdeck's gate card: stacked colored bar of verdicts, allowed / asked (you or classifier) / denied counts, and file / shell / other bucket counts, plus the last denied tool with credential-like values masked (existing `maskSecrets`). ODD addition, from the accepted proposal: the inline-write alert (count and last path, error color) lives in this card.
- **S7 — Agents.** As flightdeck's agents list: `agents · N running · M total`, one row per agent with a status mark, its construct role (or subagent type), a timeline bar (`━` with `·` padding) placed on the session's time span, and its duration; running clocks tick live (flightdeck's `elapsed.tsx`).
- **S8 — Last turn card.** As flightdeck's receipt: last or running turn duration, agents, edits, errors, cost added.
- **S9 — Session log.** As flightdeck's session log: a bordered `session log` with timestamped rows (`HH:MM:SS`, who, what): agent spawned and done, denied tool, inline write; ODD additions (assumption, from the accepted proposal): ODD task changed and RDD state changed. Bounded ring buffer; row count fits the remaining height.
- **S10 — Reuse with attribution.** "Si Reutilizar y adecuar". Reused or adapted flightdeck code keeps the MIT copyright and permission notice in each file that contains it, and the README credits flightdeck.
- **S11 — Observe-only and docs.** Every new hook passes its event to `next` unchanged; routing hooks stay as they are. New state stays in the versioned panel `atom`, logic in pure modules outside `register.js`. README describes the new panel.
