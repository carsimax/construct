# Gentle parity: deterministic admissions and review transaction

Objective: move the deterministic parts of Gentleman-Programming's ODD/RDD/JD flow that Construct still enforces only by prompt into code, adapted to Claude Code hooks, the mod, and the `odd-review` CLI. Branch: `feat/gentle-parity`, baseline `985cd7f` (main). Delivery strategy: ask-on-risk. Test runner: `node --test tests/`; `claude plugin test plugins/construct`; `claude plugin validate --strict ./plugins/construct`.

Upstream references (read-only clones in the session scratchpad; cite by SHA when the clone is gone): gentle-ai `2a3129aa42084b9c4042be51969b526e426ab9a5`, gentle-shell `63d6065f924ec366a321dd21f7396f04026c026f`, engram `23dbc73`, gentleman-guardian-angel `fbf1091`, gentle-agent-state `963e853`. Research summary: engram topic `odd/parity-map/gentle-shell-2026-10-20`.

## Specs

- **S0 — Host probes.** Source: the user's request "investiga a fondo sobre claude y sus hooks,la parte de los nuevos mods", and the research items marked UNCONFIRMED. Observe on the live host (`claude -p` with a probe plugin in the scratchpad, never shipped) and record the raw payloads in `## Log`: (a) whether a main-thread `PreToolUse` payload lacks `agent_id` while a subagent's carries `agent_id` and `agent_type`; (b) whether `PreToolUse` on `Agent` with `updatedInput` changes the prompt the subagent receives; (c) whether `SubagentStart` carries anything that correlates it with the `Agent` call (`tool_use_id`, prompt, description); (d) whether the mod `tool.check` event has `e.agentId` absent on the main thread. S3, S4, and the concurrency half of S2 depend on (a) and (c).
- **S1 — Destructive command guard, two tiers.** Port of gentle-shell `lib/destructive-command-guard.ts` and `extensions/gentle-ai.ts:1496-1506, 1535-1580, 2075-2145`. Hard deny: `rm -rf` of `/`, `~`, `$HOME`, `.`, `..`; `git reset --hard`; `git clean -fd` (and `-fdx`, `-xdf`); force push (`--force`, `-f`, `--force-with-lease` excluded only if upstream excludes it); `chmod -R 777`; `chown -R`. Confirm tier (`permissionDecision: "ask"`): SQL `DROP`/`TRUNCATE`, `DELETE` without `WHERE`, `rm -r`, `find -delete`, `git restore`, `git checkout -- <path>`, `git stash drop`/`clear`, `git push`, `git rebase`, `git branch -D`. `npm publish` is denied. The command parser unwraps `sh -c`/`bash -c`/`zsh -c`, `eval`, `find -exec`, `$(...)` and backticks, and the wrappers `sudo`, `env`, `xargs`, `timeout`, `nice`, `command`; heredoc bodies and quoted data arguments to `grep`, `rg`, `echo`, `printf` are not commands. Inside a subagent (`agent_id` present, per S0a) the confirm tier becomes deny. Assumption: lives with `secret-guard.mjs` (same hook entry), reuses its tokenizer, and never weakens an existing deny; failure mode stays as today.
- **S2 — Delegation admission.** Port of gentle-shell `lib/bounded-writer-admission.ts:60-120`, `lib/verifier-admission.ts:15-29`, `lib/writer-surfaces.ts`. A `PreToolUse` hook on `Agent` denies, with a reason naming what is missing:
  - `construct:odd-worker` or `construct:jd-fix-agent` without a `## Allowed edit surfaces` section holding at least one entry, or with an entry that is absolute, contains `..`, or is a bare `*`/`**`;
  - the same writers without `Spec: odd/tasks/<f>.md, T<n>` naming an existing regular file (not a symlink), but only when an unfinished feature document exists (the `feature-state.mjs` rule). Adaptation: upstream requires it always; Construct's small work has no feature document;
  - `construct:odd-verify` without a line `Risk: item N` (N 1-6);
  - a writer whose surfaces overlap those of a writer still open (state shared with `subagent-count.mjs`); anything unparseable counts as overlap.
  Assumption: no context-backstop bypass (upstream has one); the backstop is only a notice (S7).
- **S3 — Writer edit surfaces.** Stronger than upstream (which checks only at dispatch). A writer subagent's `Edit`/`Write`/`MultiEdit`/`NotebookEdit` on a path outside its surfaces is denied. Binding (from S0, L4): the hook reads the surfaces from the writer's own prompt, the first `user` row of `<dirname(transcript_path)>/<session_id>/subagents/agent-<agent_id>.jsonl`, and the writer type from `agent_type`. Assumptions: that transcript layout is undocumented, so a missing or unreadable file fails open (S2 already admitted the prompt); `Bash` writes are out of scope (not reliably attributable to a path); the file exists by the subagent's first tool call (to confirm live in T3).
- **S4 — Main thread does not write.** Source: the session contract "The parent orchestrates and never writes code", today prompt-only. A main-thread (`agent_id` absent, per S0a) `Edit`/`Write`/`MultiEdit`/`NotebookEdit` on a path inside the project repository and outside `odd/tasks/` is denied with a reason that names `construct:odd-worker`. Paths outside the repository (scratchpad, memory directory, home config) are allowed. Assumption: main-thread `Bash` writes are out of scope.
- **S5 — Review transaction parity.** Port of gentle-ai `internal/reviewtransaction/transaction.go:78-88, 305-900`, `risk.go:123-190, 290-310`, `receipt.go:15-60`, `internal/cli/review_facade.go:740-762`. In `lib/review`:
  - one-shot counters `full_reviews`, `refuter_batches`, `fix_batches`, `scoped_fix_validations`, `final_verifications`; a second batch of any kind makes the transaction terminal `escalated`;
  - correction budget `min(200, ceil(lines/2))` with a floor of 2;
  - the receipt records a paths digest and hashes of policy, ledger, evidence, and fix delta, and `odd-review status` reports a receipt whose hashes no longer match;
  - verbs `abandon`, `invalidate`, `capture-unachievable` (a lens that cannot run);
  - a `medium` candidate gets one focus lens, chosen as upstream does.
  Usage text, README, and the `rdd-review` skill change together.
- **S6 — Publication gate and session baseline.** Port of gentle-ai `receipt.go:132-136` (`validate --gate`) and `internal/cli/review_stop_hook.go:63-78, 130-200`, and of gentle-shell `lib/review-publication-gate.ts`. `odd-review validate --gate pre-push|pre-pr|release` fails when RDD is on and the range being published holds a review-due candidate without an approved receipt for its tree. A `PreToolUse` hook on `Bash` runs it for `git push`, `gh pr create`, and `gh release create` and denies on failure. `review-gate.mjs` stays silent for candidates whose identity equals the one recorded at `SessionStart`. Adaptation: no `pre-commit` gate, because Construct reviews committed work units. Assumption: the hook fails open on errors, as the other gates do.
- **S7 — Delivery signals.** Port of gentle-shell `lib/commit-slice-signal.ts`, `lib/context-backstop.ts`, `lib/delivered-test-lint.ts`. (a) After a successful `git commit`, `PostToolUse` adds context with the branch's authored changed lines against the default branch (lockfiles and generated files excluded) and a notice past 400. (b) One notice per session when transcript usage passes `min(150k, 15% of the context window)`. (c) A write to a test path that reads git history at a literal SHA or sets `TMPDIR` to a repository-relative path is denied.
- **S8 — Mirror drift and panel state.** Source: engram (no hook mirrors feature documents) and gentle-agent-state `scripts/hook-adapter.sh:46-64`. (a) `Stop` blocks once per turn when an `odd/tasks/<f>.md` changed during the turn and the transcript holds no `mem_save` with `topic_key` `odd/<f>/tasks` after the change. (b) The status panel shows a blocked state from `Notification` (message matching permission or approval) and `PreToolUse` on `AskUserQuestion`/`ExitPlanMode`, cleared by `UserPromptSubmit`, `PostToolUse`, and `Stop`.

Out of scope (decided in the research, L2): gentle-shell auto/yolo permission modes, capability negotiation and consent v3 transport, the ODD phase label, the skill registry hook, plugin `settings.json` `"agent"` as main thread.
