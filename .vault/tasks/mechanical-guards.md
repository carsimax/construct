# Mechanical guards (wave 1)

Objective: turn prompt-only rules into hooks: git bypass and destructive-command guard, verifier-weakening marker block, memory injection scan, and write-time edit-surface enforcement. Branch: feat/mechanical-guards. Baseline: 9299c28. Delivery strategy: single-pr. Test runner: `node --test tests/`.

## Specs

- **S1 — Git and destructive-command guard.** "Hook de git: bloquea `--no-verify`, `-c core.hooksPath=`, force-push sin lease, `reset --hard` y `clean -f`, y pide confirmación antes de `rm -rf`". New PreToolUse Bash hook `hooks/scripts/command-guard.mjs`, reusing `shell-words.mjs` (`splitCommands`, `nestedLines`, `substitutionBodies`, `GIT_VALUE_FLAGS`) so compound commands, `bash -c`, `eval`, `$(...)`, env prefixes, and `git -C dir` are covered. Assumption (recommendation applied): `deny` for verifier bypasses (`git commit --no-verify` / `-n` in a short-flag cluster, `git push --no-verify`, `--no-gpg-sign`, `git -c core.hooksPath=...` on any subcommand); `ask` for destructive commands (`rm` with both recursive and force flags, `git push --force` / `-f` / `+refspec` without `--force-with-lease`, `git reset --hard`, `git clean` with `-f`, `git checkout -- .` and `git restore .`/`--worktree .`). Applies in the main thread and in subagents. Unparseable input fails open (no output), matching the gate's non-publication path. Deny/ask use the existing `hookSpecificOutput` shape (`publication-gate.mjs:389`). Probe (2026-10-21, `claude -p`, bypassPermissions): `ask` blocks the tool both in the main thread and in a subagent.
- **S2 — Verifier-weakening marker block.** "Bloquear el cierre si el turno agregó `.skip(`, `.only(`, TODOs o stubs `Not implemented`". In `risk-line.mjs check`, scan the turn's added lines (`git diff -U0` between the marked tree and the candidate tree; `odd/tasks/` excluded as today) for code-shaped markers: focused or skipped tests (`it|test|describe|context` with `.skip(`/`.only(`/`.todo(`, `xit(`, `xdescribe(`, `@pytest.mark.skip`, `t.Skip(`), and `throw new Error('Not implemented')`-style stubs and new `TODO` lines in non-Markdown source. Markers must be anchored to code shape (not inside string literals of fixtures) to limit false positives. The check runs before the Risk-line early exit, shares the existing once-per-turn `blocked` slot, names at most 3 `path:line` hits, and fails open on any error.
- **S3 — Memory injection scan.** "Buscar texto de inyección en los aprendizajes antes de guardarlos o reinyectarlos". One pattern helper beside `stripPrivate` (`memory-store.mjs:143`). Assumption (recommendation applied): passive learnings that match are dropped; explicit `save`/`update` that match are rejected with an error naming the reason; prompt capture and session summaries get the matching line replaced with `[FILTERED]`; `context()` omits stored rows that match, so rows written before the rule never reach SessionStart context. Patterns stay narrow (instruction-override phrases, fake role/system tags, compaction-survival phrases such as "when compacting, retain"); the worker checks them against this repository's existing memory export for false positives.
- **S4 — Write-time edit-surface enforcement.** "Hacer cumplir en Write/Edit las rutas permitidas de cada worker, y negar escrituras de código del parent". `delegation-admission.mjs start` stores the SubagentStart `agent_id` in the record it marks started. A new PreToolUse `Write|Edit|MultiEdit|NotebookEdit` hook (`hooks/scripts/surface-guard.mjs`): with `agent_id`, looks up that agent's record and denies a path inside the repository that no admitted surface contains (new containment matcher; `**` spans segments; the existing `surfacesOverlap` is not a containment test); no record means allow. Without `agent_id` (main thread, verified by the probe), denies paths inside the git work tree outside `odd/tasks/`; paths outside the repository and runs outside a git repository are allowed. Fails open on errors. Known limit kept: same-type launches may swap records (existing FIFO shortcut); Bash writes are not covered.
- **S5 — Registration and docs.** New hooks registered in exec form in `hooks/hooks.json` with registration tests; `README.md` hook lists (publication gate paragraph and command-hook list), `CLAUDE.md` architecture hook list, and `skills/memory/SKILL.md` describe the new behavior.
